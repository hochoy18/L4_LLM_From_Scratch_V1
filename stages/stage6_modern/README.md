# Stage 6 — 现代 LLM 技术地图 (2022–2024)

- **对应**：Chinchilla 缩放定律 (2022) · FlashAttention (2022) · MoE (Switch/Mixtral) · LLaMA/Llama/Mistral 开源谱系 · o1 推理时计算 (2024)
- **地位**：按 ADR-0003，这一阶段以**读 + 跑**为主，补齐「现代 LLM 到底怎么被做得更强」的地图。
- **提示**：学习者已熟悉应用层（agent/RAG），本阶段是「已知」的机制补全，不是新知识。

## 目标

建立一张现代 LLM 技术地图——理解那些「不改变范式、只把 decoder 做得更强」的关键技术。

## 读 + 跑（不手写）

| 技术 | 解决什么 | 一句话 |
|---|---|---|
| **Chinchilla 缩放定律** | 模型/数据该多大才配 | 约 20 token/参数；GPT-3 其实是「模型大、数据少」——训小了 |
| **FlashAttention** | 注意力太慢太占显存 | 更省显存、更快的注意力算子（算法不架构） |
| **MoE（Mixtral 等）** | 想扩容又不想线性涨算力 | 路由到部分专家，稀疏激活：参数多、算力省 |
| **LoRA/量化** | 微调/部署太贵 | 参数高效微调、低比特部署 |
| **开源权重（LLaMA→Llama→Mistral/Qwen/DeepSeek）** | 闭源垄断 | 开放权重逼近闭源，生态爆发 |
| **推理时计算（o1 等）** | 简单问题答不好 | 让模型「多想一会儿」——训练之外的新 scaling 轴 |

## 可选跑

- 跑一个开源小模型（Llama/Mistral 的小尺寸版本），感受开源生态的现状。

## 验收

- 产出一页「现代 LLM 技术地图」：每个技术解决了什么瓶颈，挂在哪条主线上。
- 能讲清：为什么这些技术大多是「正交改进」而非「新架构」。
